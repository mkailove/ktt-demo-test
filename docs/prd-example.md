# 快团团素材生成器产品需求

**版本：** V1.0（2026-10-22）

**状态：** 本地实现已完成自动化验证；Chrome、Edge 与真机扫码验收仍待记录。本文是当前产品规格，后续修改需求时先修订本文；此状态不代表 GitHub Pages 发布批准。

**范围：** 单商品海报编辑与 PNG 导出

本文把首期目标、用户操作、字段规则和验收条件写成可以开发和检查的要求。原始聊天附图提供编辑器与“居中促销”版式的风格参考；2026-10-22 的视觉复核以第一张附图为排版参照，重点放大主图与文字、收紧卖点到价格的留白。三套模板的实现和验收以本文第 4 节为准，不依赖线上演示页面的后续变化。项目采用纯前端、根目录单文件 `index.html`、无构建步骤；公开发布另行确认。

## 1. 产品目标与范围

用户无需登录，在浏览器填写单个商品信息，上传商品主图与已有二维码，切换三种版式，实时预览并导出一张 PNG 海报。用户上传的图片和输入内容只在浏览器本地处理。

V1.0 包含基础信息、单张主图、单张二维码、最多六条卖点、价格与转化文案、三种模板、实时预览、恢复示例和 PNG 导出。刷新页面后恢复默认示例，不保存草稿。

V1.0 不包含登录、云端存储、批量生成、AI、拖拽排版、支付、后端或数据库。

## 2. 页面与用户流程

桌面宽屏显示左侧编辑区和右侧海报预览；窄屏改为上下布局，所有字段和预览都可以滚动访问。编辑区依次包含模板、基础信息、图片素材、卖点、价格和文案、恢复与导出。

1. 打开页面，载入默认文字和“居中促销”模板；主图与二维码显示占位。
2. 修改字段并上传图片，预览随输入更新；上传失败时保留上一张有效图片。
3. 切换三种版式，只改变布局和主题色，已填写内容保持不变。
4. 点击“导出 PNG”，先校验，再冻结当前内容并生成一张图片；失败时保留输入并允许重试。

首次进入可以预览占位海报；缺少主图或二维码时不能正式导出，界面需明确显示缺失项。

默认示例及“恢复示例”的目标值固定为：模板“居中促销”；顶部标签“今日开团”；团长品牌“小美优选·团长”；标题“【新疆直发】阿克苏冰糖心苹果 5斤装”；副标题“咬一口爆汁甜脆·产地现摘现发”；卖点依次为“产地直发，没有中间商加价”“冰糖心占比高，一口爆汁甜”“坏果包赔，售后无忧”；原价 39.90 元、团购价 19.90 元；团长说“我自己吃了两箱，真的甜！这个价格基本就是产地价了。”；发货信息“5斤/箱·默认圆通·48h 内发货·坏果包赔”；购买主文案“长按识别 跟团购买”、购买副文案“早买早发·手慢无”；主图和二维码为空，预览中分别显示“商品主图”“二维码”占位。

## 3. 输入字段与约束

| 字段 | 规则 | 导出条件 |
| --- | --- | --- |
| 顶部标签、团长品牌 | 可留空；上限分别为 12、24 个字符；留空时隐藏对应区域 | 超出上限时提示并阻止导出 |
| 商品标题、副标题 | 标题必填，最多 60 字；副标题可空，最多 60 字；不自动截断 | 标题须完整排入海报 |
| 商品主图、二维码 | 各上传一张图片；不按扩展名、MIME 类型、文件体积、像素数或宽高比设置固定限制 | 两张图片都必须能由当前浏览器解码，且解码后宽高有效 |
| 核心卖点 | 0 至 6 条；空条目不绘制；每条最多 35 字 | 文字不得与其他区域重叠 |
| 原价、团购价 | 原价可空；团购价必填且大于 0；最多两位小数，最大 999999.99 元 | 原价存在时不得低于团购价 |
| 团长说 | 可留空；最多 48 字；允许换行；留空时隐藏该区 | 完整排入海报 |
| 发货信息 | 可留空；最多 40 字；留空时隐藏该行 | 完整排入海报 |
| 购买主文案、购买副文案 | 可留空；上限分别为 16、24 字；留空时隐藏对应文字，二维码仍显示 | 完整排入海报 |

“字符”按 Unicode 码点计数；单行字段去除首尾空白后校验，不接受换行。团长说保留用户换行，统一按 `\n` 计数；所有字段都不自动截断。输入超限时保留用户内容并给出字段级提示。字段满足字数上限仍可能因版式空间不足而无法导出，此时预览标出溢出的字段，要求用户缩短内容。错误状态下可以继续编辑和预览，但不能生成正式 PNG。

## 4. 模板与素材规则

模板为“居中促销”“左图清单”“大图爆款”。三套模板共用同一份商品数据，切换模板不得清除字段、图片或卖点。视觉基线是下表和 720 × 1280 像素成图规则；原始附图只解释风格，不作为逐像素验收图。所有坐标以导出 PNG 左上角为原点，单位为像素。

| 共用视觉规则 | 固定值 |
| --- | --- |
| 画布与安全区 | 白色背景，文字与二维码图案距画布四边至少 32；装饰背景可进入安全区，但不得越出画布 |
| 字体 | 中文优先使用系统的“Microsoft YaHei”，缺失时使用系统无衬线字体；标题粗体、价格粗体、正文常规字重 |
| 字号下限 | 标题 30、价格 42、卖点 18、说明及购买副文案 16；默认视觉字号为标题 34、价格 56、居中版卖点 22、副标题 22、顶部品牌 27、黄色标签 21；文字可以换行，不可缩到下限以下 |
| 共用区 | 顶部色条 y=0–90，品牌与黄色标签以 y=45 为竖直中心；单行标题从 y=106 排版，两行标题仍从 y=100 排版以免碰到副标题；单行标题下的副标题灰色框 y=176–214 且文字竖直居中，两行标题时灰框 y=184–222；价格圆角区 y=892–976，团购价、原价及优惠徽标沿同一竖直中心线排列；团长说色块在 y=984–1056，最多两行文字按实际行数垂直居中；y=1060 的浅色虚线从画布左边延伸到右边；二维码购买区 y=1064–1268，发货信息排在购买区右侧文案下方 |
| 色彩与表面 | 保留三模板主题色；正文深色 `#242832`、主图占位浅灰 `#EFF2F5`、说明底色 `#F3F5F8`、白底 `#FFFFFF`。用圆角和轻阴影区分主图、价格与购买区，不使用装饰性粗边框 |
| 二维码购买区 | 浅灰底圆角区，二维码在左、购买主副文案在右；三套模板位置和大小相同。二维码仍为 176 × 176 像素，外围不另画白色方块或白色静区，以购买区背景色承接码图；上传图自身的背景色不改 |

| 模板 | 主题色 | 主图与卖点区（y=224–880） |
| --- | --- | --- |
| 居中促销 | 红色 `#FF4B5B` | 默认三条短卖点时，主图容器居中于 x=100–620、y=226–746，3:4 无图占位约 390 × 520；自动识别或原图比例的横图可扩展容器至 x=32–688，避免主图与卖点之间出现大片留白。卖点与主图留 28 像素空隙，从 y=774 向下排列。卖点增加或换行时，主图容器向上收缩，为卖点让出空间，卖点最晚在 y=880 结束 |
| 左图清单 | 青色 `#20A9C7` | 主图在左侧 x=32–428、y=224–880；卖点在右侧 x=448–688、y=240–880 自上而下排列 |
| 大图爆款 | 橙色 `#FF783F` | 主图容器横向占 x=32–688、y=224–716；图片按所选比例完整展示或裁切，竖图的实际可见宽度可能小于容器；卖点与主图留 28 像素空隙，从 y=744 向下排列，最晚在 y=880 结束；卖点增加时主图区向上收缩 |

各区域按上表保持顺序。居中促销和大图爆款按卖点实际行数分配主图与卖点高度；主图容器高度不低于 320，仍放不下时指出卖点并禁止导出。空的可选字段释放空间给同一区域其他内容。出现标题、卖点或说明文字放不下时，指出字段并禁止导出，不覆盖后续区域。切换模板后重新排版并重新校验。

主图比例提供自动识别、3:4、1:1、保留原图比例四项；适配方式提供完整展示和铺满裁切两项。自动识别在无图时按 3:4 展示；源图宽高比为 0.9–1.1 时按方图展示，其余按源图比例展示。自动识别和保留原图比例的容器宽高比限制在 0.55–1.3。所有模式都保持原图宽高比。完整展示允许留白，铺满裁切默认从中心裁切。

二维码可以上传团长二维码或商品码，不限制原图的格式、体积、像素数与形状。导出时将它等比完整绘制在 176 × 176 像素区域内，外围与购买区使用同一浅灰底色，不额外绘制白色留白；不得裁切、拉伸或叠加文字，并关闭二维码图像插值。原图自身的白色背景仍会保留。非方形、低清晰度或缺少白色静区的原图可能难以识别，正式导出仍以第 6 节的真机扫描用例为准。

选择新图片后，系统直接交由浏览器解码；只有解码成功且宽高有效才替换旧图，不设置固定格式、体积或尺寸门槛。取消选择或处理失败时保留旧图，并提示无法解码。快速连续选择时，较早的处理结果不得覆盖最后一次选择。

卖点按当前顺序编号，删除后立即重排。达到六条时禁用新增；空卖点不占用海报空间。

## 5. 价格、预览与导出

金额计算时换算为整数分。原价大于团购价时显示原价删除线和节省金额；原价为空或与团购价相等时不显示优惠。原价低于团购价或团购价无效时提示并阻止导出。优惠提示不替代用户填写的购买主文案。

预览与导出使用相同的 Canvas 绘制规则。页面输入变化后，预览尝试展示最新输入；无效字段标出错误，图片只使用最后一次通过解码的有效文件。文字、价格、图片与二维码不得覆盖或越过画布。长内容放不下时指出对应字段，禁止导出；不擅自缩到无法阅读的字号。

导出要求：

- 只包含白底海报，PNG 尺寸固定为 720 × 1280 像素，图片不包含编辑器界面。
- 点击导出时冻结当前内容，避免生成期间的编辑改变本次结果。
- 生成期间禁用重复点击；失败时保留编辑内容并允许重试。
- 成功时发起浏览器下载；文件名格式为 `团购海报_模板_标题_YYYYMMDD-HHmmss.png`，时间使用用户设备本地时间。文件名标题只取前 20 个字符，移除 Windows 文件名非法字符和末尾空格、句点；标题清理后为空时用“商品”代替。

点击“恢复示例”立即覆盖文字、价格、模板、卖点和图片设置，并清空已上传的主图与二维码，不显示确认弹窗。

## 6. 验收用例

| 编号 | 操作 | 通过条件 |
| --- | --- | --- |
| AC01 | 首次打开与刷新 | 显示默认文字和占位预览；刷新后不保留上次编辑 |
| AC02 | 三模板往返切换 | 布局和主题色变化，商品数据及图片保持一致 |
| AC03 | 上传浏览器可解码与不可解码的主图，包括原先未放行的格式 | 可解码图等比显示且不按扩展名、体积或像素数拦截；不可解码图有提示且旧图保留 |
| AC04 | 上传测试二维码并导出 | 保存的 PNG 中码图完整、外围没有额外白色方块且与购买区同色；按本节扫码步骤，手机可识别出指定网址 |
| AC05 | 调整比例和适配 | 四种比例与两种适配符合选择，无拉伸 |
| AC06 | 增删卖点至六条 | 序号正确；达到上限后不能继续添加 |
| AC07 | 输入异常价格及长文本 | 指出字段；不产生重叠或截断的正式 PNG |
| AC08 | 恢复示例 | 点击后直接恢复约定状态、清空已上传图片，没有确认弹窗 |
| AC09 | 完整导出 | PNG 为 720 × 1280、白底，不含编辑器界面；文字、素材、模板和价格与点击时预览一致，文件名符合第 5 节 |
| AC10 | 连续上传或重复导出 | 旧异步结果不覆盖新图；同一时间只运行一个导出任务 |
| AC11 | 窄屏查看 | 360px 宽度下字段、按钮和预览均可访问 |
| AC12 | 对照当前视觉参考检查默认海报 | 顶部文字在各自色块内居中、标题和副标题与主图有留白、卖点首行离主图约 28 像素；价格栏、团长说和购买区的层次与虚线符合第 4 节，三版式预览与导出内容一致 |

扫码验收固定使用内容为 `https://example.com/ktt-v1-qr`、原图宽高至少 320 像素的正方形测试二维码。在电脑屏幕上以 100% 像素倍率显示保存 PNG 的二维码区域，不缩小该区域；在普通室内照明下使用一部手机的系统相机，距屏幕 20–40 厘米尝试三次；至少两次在 5 秒内识别出完全一致的网址才通过。若测试设备无法读取其他已知有效二维码，先排除设备或显示屏问题，再执行本用例。测试二维码文件放在项目约定的 `work/`，不纳入 Git。

本地验收须在 Windows 的 Chrome 与 Edge 桌面稳定版完成，并用横图、方图、竖图检查三套模板。Safari 与 Android 浏览器不列入 V1.0 必测范围。商品图片和二维码只在浏览器本地处理。

## 7. 质量与隐私

- 商品主图、二维码和输入文案只在浏览器本地处理，不向远程服务上传素材，不加载外部分析脚本。
- 输入字段有可见标签和键盘焦点；错误信息包含字段名和处理建议，不只靠颜色区分。
- 导出中与导出失败都显示状态；失败后编辑区仍可操作。
- 目标浏览器为当前主流 Chrome 与 Edge 桌面版。360px 宽窄屏须可访问和滚动。
- 图片上传、三模板预览和导出期间，页面不得出现未处理的控制台错误。

## 8. 开发与发布边界

第一版遵循项目 [AGENTS.md](../AGENTS.md)：根目录一个 `index.html`，其中包含 HTML、CSS 和原生 JavaScript，可直接在浏览器打开。不得引入 React、Vite、构建脚本、运行时第三方依赖、`package.json` 或依赖锁文件。`README.md` 记录使用与验证方法，`tests/` 保存基于 Node 内置测试功能的持久测试和手工验收清单。应用代码变更后执行 `node --test`，并在浏览器逐项检查上传、模板、预览、扫码和导出。

本地验收完成后，另行列出 GitHub 仓库、分支、Pages 来源和准确上传文件清单，经所有者确认后才执行 `git push` 或公开发布。
