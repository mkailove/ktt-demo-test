# 快团团素材生成器产品需求示例

**版本：** V1.0 草案

**状态：** 评审示例，产品负责人确认后才能作为开发基线

**范围：** 单商品海报编辑与 PNG 导出

本文示例把首期目标、用户操作、字段规则和验收条件写成可以开发和检查的要求。它遵循项目当前约定：纯前端、根目录单文件 `index.html`、无构建步骤；公开发布另行确认。

## 1. 产品目标与范围

用户无需登录，在浏览器填写单个商品信息，上传商品主图与已有二维码，切换三种版式，实时预览并导出一张 PNG 海报。用户上传的图片和输入内容只在浏览器本地处理。

V1.0 包含基础信息、单张主图、单张二维码、最多六条卖点、价格与转化文案、三种模板、实时预览、恢复示例和 PNG 导出。刷新页面后恢复默认示例，不保存草稿。

V1.0 不包含登录、云端存储、批量生成、AI、拖拽排版、支付、后端或数据库。

## 2. 页面与用户流程

桌面宽屏显示左侧编辑区和右侧海报预览；窄屏改为上下布局，所有字段和预览都可以滚动访问。编辑区依次包含模板、基础信息、图片素材、卖点、价格和文案、恢复与导出。

1. 打开页面，载入默认文字和“居中促销”模板；主图与二维码显示占位。
2. 修改字段并上传图片，预览随输入更新；上传失败时保留上一张有效图片。
3. 切换三种版式，只改变布局和主题色，已填写内容保持不变。
4. 点击“导出 PNG”，先校验，再冻结当前内容并生成一张图片；失败时保留输入并允许重试。

首次进入可以预览占位海报；缺少主图或二维码时不能正式导出，界面需明确显示缺失项。

## 3. 输入字段与约束

| 字段 | 规则 | 导出条件 |
| --- | --- | --- |
| 顶部标签、团长品牌 | 可留空；上限分别为 12、24 个字符；留空时隐藏对应区域 | 超出上限时提示并阻止导出 |
| 商品标题、副标题 | 标题必填，最多 60 字；副标题可空，最多 60 字；不自动截断 | 标题须完整排入海报 |
| 商品主图、二维码 | 各上传一张 JPG、PNG 或 WebP；单张不超过 10 MB，解码像素不超过 1600 万 | 两张图片都必须可解码 |
| 核心卖点 | 0 至 6 条；空条目不绘制；每条最多 35 字 | 文字不得与其他区域重叠 |
| 原价、团购价 | 原价可空；团购价必填且大于 0；最多两位小数，最大 999999.99 元 | 原价存在时不得低于团购价 |
| 团长说、发货信息、购买主副文案 | 均可编辑；允许留空，留空时隐藏对应的非必要区域 | 所有显示文字须完整排入海报 |

输入超限时保留用户内容并给出字段级提示，不静默截断。错误状态下可以继续编辑和预览，但不能生成正式 PNG。

## 4. 模板与素材规则

模板为“居中促销”“左图清单”“大图爆款”。三套模板共用同一份商品数据，切换模板不得清除字段、图片或卖点。每套模板都要检查标题、主图、卖点、价格和二维码购买区的相对位置。

主图比例提供自动识别、3:4、1:1、保留原图比例四项；适配方式提供完整展示和铺满裁切两项。自动识别在无图时按 3:4 展示；源图宽高比为 0.9–1.1 时按方图展示，其余按源图比例展示。自动识别和保留原图比例的容器宽高比限制在 0.55–1.3。所有模式都保持原图宽高比。完整展示允许留白，铺满裁切默认从中心裁切。

二维码始终完整显示并保留白色静区，不使用主图的裁切设置。选择新图片后，系统先完成格式、大小和解码检查，再替换旧图；取消选择或处理失败时保留旧图。快速连续选择时，较早的处理结果不得覆盖最后一次选择。

卖点按当前顺序编号，删除后立即重排。达到六条时禁用新增；空卖点不占用海报空间。

## 5. 价格、预览与导出

金额计算时换算为整数分。原价大于团购价时显示原价删除线和节省金额；原价为空或与团购价相等时不显示优惠。原价低于团购价或团购价无效时提示并阻止导出。优惠提示不替代用户填写的购买主文案。

预览与导出使用相同的 Canvas 绘制规则。页面输入或图片变化后，预览展示最新有效状态。文字、价格、图片与二维码不得覆盖或越过画布。长内容放不下时指出对应字段，禁止导出；不擅自缩到无法阅读的字号。

导出要求：

- 只包含白底海报，PNG 尺寸固定为 720 × 1280 像素。
- 点击导出时冻结当前内容，避免生成期间的编辑改变本次结果。
- 生成期间禁用重复点击；失败时保留编辑内容并允许重试。
- 成功时发起浏览器下载；文件名格式为 `团购海报_模板_标题_时间戳.png`，并移除文件名非法字符。

恢复示例会覆盖文字、价格、模板、卖点和图片设置，并清空已上传的主图与二维码。存在修改时先提示将覆盖当前内容；取消后保持现状。

## 6. 验收用例

| 编号 | 操作 | 通过条件 |
| --- | --- | --- |
| AC01 | 首次打开与刷新 | 显示默认文字和占位预览；刷新后不保留上次编辑 |
| AC02 | 三模板往返切换 | 布局和主题色变化，商品数据及图片保持一致 |
| AC03 | 上传有效与无效主图 | 有效图等比显示；无效图有提示且旧图保留 |
| AC04 | 上传真实二维码 | 导出图中完整显示，手机可以识别 |
| AC05 | 调整比例和适配 | 四种比例与两种适配符合选择，无拉伸 |
| AC06 | 增删卖点至六条 | 序号正确；达到上限后不能继续添加 |
| AC07 | 输入异常价格及长文本 | 指出字段；不产生重叠或截断的正式 PNG |
| AC08 | 恢复示例 | 确认后约定状态恢复；取消后无变化 |
| AC09 | 完整导出 | PNG 为 720 × 1280、白底，内容与点击时预览一致 |
| AC10 | 连续上传或重复导出 | 旧异步结果不覆盖新图；同一时间只运行一个导出任务 |
| AC11 | 窄屏查看 | 360px 宽度下字段、按钮和预览均可访问 |

本地验收须在 Chrome 与 Edge 桌面浏览器完成，并用真实二维码及横图、方图、竖图检查三套模板。商品图片和二维码只在浏览器本地处理。

## 7. 质量与隐私

- 商品主图、二维码和输入文案只在浏览器本地处理，不向远程服务上传素材，不加载外部分析脚本。
- 输入字段有可见标签和键盘焦点；错误信息包含字段名和处理建议，不只靠颜色区分。
- 导出中与导出失败都显示状态；失败后编辑区仍可操作。
- 目标浏览器为当前主流 Chrome 与 Edge 桌面版。360px 宽窄屏须可访问和滚动。
- 图片上传、三模板预览和导出期间，页面不得出现未处理的控制台错误。

## 8. 开发与发布边界

第一版遵循项目 [AGENTS.md](../AGENTS.md)：根目录一个 `index.html`，其中包含 HTML、CSS 和 JavaScript；无构建步骤。`README.md` 记录使用与验证方法，`tests/` 保存持久测试和手工验收清单。应用代码变更后执行 `node --test`，并在浏览器逐项检查上传、模板、预览和导出。

本地验收完成后，另行列出 GitHub 仓库、分支、Pages 来源和准确上传文件清单，经所有者确认后才执行 `git push` 或公开发布。

## 9. 产品确认项

以下事项会影响视觉和验收；确认结果写回文档，线上页面未来的变化不会自动替换已确认的基线：

- 以哪一版参考页面或截图作为三套模板的视觉基准。
- 720 × 1280 是否为最终导出尺寸；二维码在成图中的最终尺寸及真机识别测试设备。
- 是否将 Safari 与 Android 浏览器列入 V1.0 必测范围。

本示例用于评审，不代表原始 PRD 已获得产品签署或公开发布批准。
